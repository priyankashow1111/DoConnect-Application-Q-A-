--- Semantic Versioning (SemVer) Strategy ---

Format: MAJOR.MINOR.PATCH

  MAJOR — Breaking change (e.g., removing an endpoint, changing response schema)
  MINOR — New backward-compatible feature
  PATCH — Bug fix or minor internal change

Current: 1.0.0
  - Initial release with /health and /timings endpoints

Next version after introducing a new feature (e.g., adding /api/metro/lines endpoint):
  → 1.1.0  (MINOR bump — new feature, no breaking changes)

If a bug is fixed in that release:
  → 1.1.1  (PATCH bump)

If the API response schema is restructured (breaking change):
  → 2.0.0  (MAJOR bump)
